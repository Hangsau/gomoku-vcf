## 本機跑

本機設定放 `game/duel-server/.dev.vars`（不進 git）。**`wrangler dev --var` 在這版不會生效**（2026-11-11 實測 env 拿到 null），要測閒置就在 .dev.vars 寫 `IDLE_MS=8000`、`IDLE_ASK_MS=5000` 再重開 wrangler dev；測完拿掉，不然其他測試會被閒置規則踢掉。


```bash
python -m http.server 8791 --bind 127.0.0.1                     # 在 repo 根目錄
npx wrangler@4.158.0 dev -c game/duel-server/wrangler.toml --ip 127.0.0.1 --port 8787 --var BANK_URL:http://127.0.0.1:8791
```

開 `http://127.0.0.1:8791/duel.html`。兩個玩家要用兩個不同瀏覽器（或無痕視窗），同一個瀏覽器的分頁算同一個人。

## 兩種房間

**五子棋**：普規、連珠、塔拉、塔拉山口、Swap2。黑棋自己點到禁手只提醒不判輸；非擋不可的點是禁手（抓禁）判黑輸。再來一局交換座位。

**研棋**（使用者 2026-11-11）：
- 不計時、自訂時間的五子棋房（5+5、10+10 不行），對局中可以「申請研棋」；對方同意＝這盤不計勝負、進入研棋；拒絕後 30 秒內不能再申請。
- 任何時間設定下完，結果視窗按「研棋」直接覆盤（勝負照舊）。
- 研棋中兩人共用棋盤、誰都能下、黑白輪流、不管禁手；上一手／下一手／回到實戰；退回去再下會取代後面的手順；實戰之後的手標數字。任一方按「結束研棋」回到下完狀態。
- 伺服器：`worker.js` 的 `studyMsg`、`enterStudy`，房間狀態多一個 `study`。

**閒置退出**（使用者 2026-11-11）：坐在位子上 10 分鐘沒動作就問「還在嗎？」，60 秒沒回應就離座；對局中離座＝判負（對方看到「X 太久沒回應」）。五子棋對局中只看輪到的人（從上一手算起）；等人從開始等算起；下完、研棋、VCF 明鏡台看自己最後一個操作。伺服器用 Durable Object 的 alarm 定時檢查（建構時設的 setInterval 不會跑）。大廳卡片顯示「等了幾分」。

**VCF 明鏡台**（2026-11-12 使用者：兩種玩法並存，開房時選；房間設定 `vcf.vmode`，舊客戶端沒送＝`eight`，不認得的值伺服器回 `bad` 拒絕）：

| `vmode` | zh | ja | ko | en | 小字（zh） |
|---|---|---|---|---|---|
| `line` | 一線天 | 一線天 | 일선천 | Sky Gap | 同一題・先解開的得分 |
| `eight` | 八仙渡 | 八仙渡 | 팔선도 | Eight Immortals | 各解各的・先解開 N 題的贏 |

兩種共通：
- 題目段位初段～傳說，一律 20 手內（題庫 `game/p/段位.json` 第 3 欄 ≤ 20）；目標 3／5／10、每題思考上限 1／3／5 分鐘（預設 3 分鐘）兩種共用同一組選項。
- 明鏡台規則：想的時候不扣時間，第一手落下後 5 秒、每手 +1 秒（照 Rush 單人明鏡台）。每題思考上限到了算這題時間到。
- 倒數 3 秒後兩人同時開始。開局抽 N×3 題，做到剩 3 題就往後補，題目不會用完（`vcf.js` 的 `initList`、`ensureList`）；傳說段 20 手內只有 47 題，常玩會重複。
- 不是四的手照 Rush 防呆擋下、不算錯。玩家比賽中看不到對手下在哪；觀戰者看得到（伺服器只把 seq 送給不在座位上的人），點上方玩家列換看另一位（2026-11-13 使用者）。
- 比賽結束：棋盤變成逐題看解法（◀ ▶ 換題；正解／我的／對手）。正解先用解開那人的手順，兩人都沒解開就用引擎算。結束才送 `review`（整串題目＋兩人手順）。
- 伺服器：`worker.js` 的 `vcfStart`、`vcfBegin`、`vcfMsg`、`vcfFinish`（一線天另有 `vcfLineStep`），每人各自題號與計時（`vs.p[座位]`）；兩種玩法共用同一份題號／計時／log／review，一線天只是兩人題號永遠相同。

**八仙渡（`eight`，2026-11-11 的競速）**：兩人做同一串題目、同樣順序，各自往下做，先解開 N 題的贏。下錯（對方連五、被禁手、沒四了）、時間到、按「放棄這題」＝這題失敗，停 1.2 秒直接下一題，沒有額外懲罰。比賽中對手那條顯示他做到第幾題。

**一線天（`line`，2026-11-11 的搶答接回來）**：兩人同一題，先解開的人得 1 分，然後兩人一起換下一題（停 5 秒公開這題解法：有人解開就放他的手順，沒人解開用引擎算）；先拿到目標分數的贏。
- 下錯／時間到＝這題出局，只能等；對手還可以繼續解。兩人都出局、或到了每題思考上限還沒人解開＝這題沒人得分，公開正解後一起換題。
- 沒有「放棄這題」按鈕（舊搶答版就沒有；伺服器也忽略一線天房送來的 `vskip`）。
- 對手先解開時，還沒做完的人這題記成 `late`（慢了一步）；他下過的手靠 `vprog` 帶 `seq` 回報，賽後逐題看解法看得到。出局的人留的是他下到出局為止的手。
- 狀態多 `vs.phase`（`play`／`reveal`）與 `vs.rv`（`{ winner, seq }`，只在 `reveal` 送）。
- 跟舊搶答版不一樣的地方：公開解法改成走現在的 `vs`／`review` 資料格式；最後一題有人拿到目標分數直接進結束畫面（不再停 5 秒公開，賽後逐題看解法看得到）。

- 閒置退出、離座判負、再來一局兩種玩法行為一致。
- 本機測試腳本：`docs/design/duel-modes-2026-11-12/check/`（Playwright＋系統 Chrome，`node run.mjs`；http.server 8793、wrangler dev 8789、`.dev.vars` 的 `BANK_URL` 指 8793；頁面的 WebSocket 由腳本從 8787 改接 8789）。

## 還沒做 / 上線前要決定

- **VCF 防作弊**：第一版相信前端回報的解法；要擋就把 `vcfscore.wasm` 放進 Worker 重驗 `seq`（先量 CPU 時間再決定要不要升 Workers Paid）。
- **停用題**：伺服器抽題沒有排除 `/blocked` 的題。
- 房間只存在記憶體，伺服器重開（例如部署）時進行中的房間會消失。
- 伺服器沒有限制每人送訊息的頻率（人多了再加）。

## 同一玩家開兩個畫面（2026-11-12）

同一瀏覽器兩個分頁、或 LINE／FB 內建瀏覽器重複點連結，會用同一個玩家 ID 連線；伺服器只留最新那條，舊的用關閉碼 4000 踢掉。前端收到 4000 不自動重連（以前會，兩邊每 2 秒互踢、落子被吃掉），改顯示「已在別的畫面開啟」＋「改用這裡」；切回該畫面（visibilitychange／pageshow）會自動接手。沒連線時點棋盤提示「連線中，請稍候」。測試腳本在 docs/design/duel-replaced-2026-11-12/check/run.mjs（同一個 browser context 開兩頁＝同 ID）。

伺服器配合（同日）：前端連線網址帶 `v=2`。同一玩家已經有 `v=2` 連線時，沒帶 `v` 的連線（還沒重新整理的舊頁面，會每 1.6 秒自動重連）回 409，不讓它把新頁面踢掉；舊對舊、新取代舊、新取代新照舊。

**部署伺服器後不會馬上換版**：Cloudflare 2026-10-30 起預設讓使用中的 Durable Object 延後最多 5 分鐘才換新程式（這裡的大廳一直有人連著，所以每次都等滿 5 分鐘）；換版那一刻所有房間與連線重置。部署後要驗證就等 5 分鐘，或用 `wrangler tail --format json` 看 `entrypoint: Hall` 那筆的 `scriptVersion.id` 是不是新版。要立刻換可在 wrangler.toml 設 `[durable_objects.code_update_strategy] mode = "immediate"`（未設）。
