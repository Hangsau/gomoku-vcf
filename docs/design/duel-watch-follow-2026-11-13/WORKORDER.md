# 施工單：兩儀殿 VCF 觀戰自動追焦（一線天、八仙渡）

**立即執行、不要只輸出計畫、不要等確認。沒改檔案就是失敗。** 進度寫本資料夾 `PROGRESS.md`，最後寫 `REPORT.md`。

## 背景（使用者 2026-11-13 定的規則）

兩儀殿 VCF（明鏡台）有兩種玩法：一線天（`line`：兩人同一題，先解開的得分）、八仙渡（`eight`：各解各的，先解開 N 題的贏）。觀戰者現在固定看其中一位玩家的棋盤，要自己點上方玩家列才換（2026-11-13 稍早做的，見 `docs/duel.md`「觀戰者…點上方玩家列換看另一位」與 `docs/design/duel-watch-2026-11-13/`）。

使用者要「自動追焦」：觀戰畫面自動跟著該看的那位。

### 一線天
1. 每題開始：顯示題目本身（兩人都還沒下）；**誰先落子就跟誰**。
2. 跟著的人**出局**（下錯／時間到）→ 切去看另一位。
3. 有人解開、或兩人都出局 → 照現有流程公開解法、換下一題；下一題重新從第 1 點開始。
4. 隨時可以手動切。

### 八仙渡
1. 跟**領先**的那位（解開題數多的）。
2. **同分**時繼續跟剛才跟的那位，不換（開局 0:0 時跟哪位：照現在的預設）。
3. 另一位**超車**（題數真的比較多了）才切過去。
4. 隨時可以手動切。

### 手動與自動（兩種玩法相同）
- 觀戰者手動點了某位玩家 → **停止自動**，這一局一直看他選的那位（換題也不跳）。
- 畫面上有一顆「自動」可以按回自動追焦；按了立刻依上面的規則決定該看誰。
- 新的一局（再來一局）回到自動。
- **要一眼看得出現在在看誰**——使用者 2026-11-13 補充：「現在的手動追焦 不好知道現在在看誰的」。現有的選中樣式不夠明顯，要改到明顯：
  - 兩位玩家的列（上方、下方）中，**正在看的那位**整列有金色外框＋一個「觀看中」標籤（文字，不是只有顏色）；沒在看的那位維持一般樣式且看得出可以點（例如列尾有「看他」字樣或眼睛圖示）。
  - 棋盤附近（題號／狀態那一行）明寫「正在看：暱稱」。
  - 一線天每題開頭還沒有人落子時，兩列都不標「觀看中」，狀態行寫「等第一手」。
  - 自動追焦中，狀態行加「自動」小標；手動時不顯示小標，改顯示可按的「自動」鈕。
  - 切換對象的那一刻有簡短提示（沿用頁面既有的 `flash`／`toast`，例如「改看 Bob」），自動切、手動切都有。
  - 新文字四語：觀看中、看他、正在看：{name}、等第一手、改看 {name}。

## 範圍

- 只影響**觀戰者**（不在座位上的人）在 VCF 對局**進行中**的畫面。玩家自己的畫面、五子棋對局、賽後逐題回看、`#replay=` 回看、VCF 回看的「自己擺」都不變。
- 先確認觀戰者手上有沒有足夠的資料判斷「誰先落子」「誰出局」「誰領先」（伺服器送給觀戰者的房間狀態與 `seq`）。**如果只靠前端就做得到，不要改伺服器。** 一定要伺服器多送欄位才做得到時，改動要最小、只新增欄位、舊頁面收到新欄位不會壞，並在 REPORT 開頭用粗體寫明「伺服器有改、需要部署對戰伺服器」。

2. 寫 `check/check_follow.mjs`（Playwright；三個 context：A、B 兩位玩家＋C 觀戰；本機靜態伺服器＋本機對戰伺服器；寫法照 `docs/design/duel-vcf-study-2026-11-13/check/check_study.mjs`；用本機引擎算真解來回報解開；截圖只存自己的 `check/`）：
