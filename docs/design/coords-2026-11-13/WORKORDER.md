# 施工單：棋盤座標（統一顯示＋設定頁開關）

**立即執行、不要只輸出計畫、不要等確認。沒改檔案就是失敗。** 進度寫本資料夾 `PROGRESS.md`，最後寫 `REPORT.md`。

## 背景（使用者 2026-11-13）

「遊戲的棋盤似乎都沒有座標？要不要把棋盤統一都做座標？」→ 主 session 建議做並加開關 → 使用者：「好 就做顯示開關 另外 要小心擠掉不同大小螢幕的頁面」。

現況（動手前自己再確認）：
- 有座標：VCF 教學的 9×9 小盤（`game/learn/learn.js`，下緣字母、左緣數字）、詰題試煉場（`score.html`）。
- 沒座標：`game.html` 的解題棋盤（各模式）、象牙塔研究盤、覆盤研究盤；`duel.html` 的對戰棋盤（五子棋、VCF）、觀戰、賽後回看、`#replay=` 回看。
- 每張棋盤樣式在 `game/skin.js` 已有座標字顏色 `label`。

## 做完的樣子

- `game.html`、`duel.html` 上面列的每一種 15×15 棋盤都畫座標：**直行 A–P（跳過 I，即 `ABCDEFGHJKLMNOP`）由左到右；橫列 1–15 由下到上**；字母在**下緣**、數字在**左緣**（跟教學盤同一套寫法，跟 `score.html` 的 `coordOf` 一致——A1 在左下角。先確認 `game.html`／`duel.html` 內部的列號方向，別畫反）。
- 字的顏色用目前棋盤樣式的 `label`；換棋盤立刻跟著換。字不可以被邊上的棋子蓋住、不可以壓到格線或星位、不可以超出棋盤底色範圍。
- **設定頁（共用的 `game/settings.js`）加一列開關「棋盤座標」**，放在「棋具」那一組裡（棋具的下一列）。存 localStorage `vcfgame.coords`（`'1'`／`'0'`），**預設開**。切了立刻生效（當下畫面的棋盤馬上重畫），`game.html`、`duel.html` 兩頁共用同一個設定；在兩儀殿對局中從齒輪進設定切換也立刻生效、不影響對局。
- 開關是真的開關元件（`role="switch"` 或 checkbox），觸控 ≥ 44px，四語文字（zh「棋盤座標」／en／ja／ko）。
- **不受開關影響、維持原樣的**：VCF 教學的小盤（課文會叫人找座標，一律顯示）、`score.html`（工具頁，一律顯示）、商店與棋具頁的小預覽盤（一律不顯示）、分享卡圖片。
- 畫座標的程式只寫一份、兩頁共用（放 `game/skin.js` 的棋盤繪製裡或它旁邊的共用函式；怎麼切自己定，在 REPORT 說明）。

## 最重要的要求：不可以擠壞任何螢幕

使用者明講：「要小心擠掉不同大小螢幕的頁面」。

- 座標要用到棋盤四周的空間。先量：現在棋盤外緣到最外圈格線的留白有多少、夠不夠放字（字高約 10–12px）。**優先用現有留白**；不夠才縮格距。
- 硬性門檻（開關開著時，跟改動前比）：
  - 任一畫面、任一尺寸，**格距（相鄰兩條線的距離）不得小於改動前的 95%**。
  - 棋盤可點的點，點擊判定範圍不變小於改動前的 95%。
  - **開關關掉時，棋盤的大小、位置、格距要跟改動前逐像素相同**（改動前先量基準存檔）。
- 要驗的尺寸（直式）：320×568、360×640、375×667、390×844、412×915、768×1024；另加一個桌機 1280×800。每個尺寸 × 四語 × 開／關：
  - 整頁不捲動（`scrollHeight <= clientHeight`、`scrollWidth <= clientWidth`）——**僅限改動前本來就不捲動的組合**；改動前就會捲的（如果有，例如 320 寬）列出來，要求是「不比改動前更糟」（超出的像素數不增加）。
  - 棋盤完整在畫面內、沒有跟上下的列（玩家列、工具列、按鈕）重疊；所有既有按鈕仍完整在畫面內。
- 要驗的畫面：`game.html` 解題畫面（至少煉獄之門、練習、象牙塔各一）、象牙塔答錯後的研究盤、覆盤研究盤；`duel.html` 五子棋對局、VCF 對局、觀戰（含「正在看」狀態行與「自動」鈕出現時）、賽後逐題回看（含「自己擺」工具列）、`#replay=` 回看。
- 最擠的情況要特別截圖自己看：320×568 與 360×640 的兩儀殿 VCF 觀戰、象牙塔研究盤。

## 限制（違反任何一條都算失敗）

- 禁止任何 git 操作（含 `git status`、`git diff`）。禁止部署。本機 `wrangler dev` 可以。
- 行程規則：禁止用程式名稱關行程；只准關自己啟動的 PID。腳本前景執行＋逾時。不對系統 Python 裝套件。
- 只准改／新增：`game/skin.js`、`game/settings.js`、`game.html`、`duel.html`、`score.html`（只有換 `skin.js?v=` 版號）、`docs/design/coords-2026-11-13/` 底下的 `PROGRESS.md`、`REPORT.md`、`check/`。改了 `skin.js` 要同步換 `game.html`、`duel.html`、`score.html` 裡的 `skin.js?v=` 版號；改了 `settings.js` 要換兩頁載入它的版號。
- 不准碰：`game/duel-server/`、`game/worker/`、`game/learn/`、`game/shop.js`、`game/skin-picker.js`。
- `duel.html`：`// showInApp();`、觀戰自動追焦、喇叭小框、VCF 回看的「自己擺」、`recordToday`（剛被另一張單改過，先讀現況）都不要動行為。
- 棋盤上既有的標記（最後一手、連五框、手順數字、禁手叉、提示圈、鬼影子）位置與大小要跟著新的格距正確對位，不可以錯位。
- `RushSkin.drawBoard` 等共用函式若要加參數，預設值必須讓沒改到的呼叫端（`score.html`、`learn.js`、`shop.js`、`skin-picker.js`）畫出跟以前一樣的結果。
- 不要重跑別的資料夾的檢查腳本去覆寫它們的截圖。

## 檢查（結果全部貼進 REPORT.md）

1. 語法：`node --check` 各 js 與兩頁抽出的 script。
2. **改動前基準**：動手前先寫好量測腳本，對上面每個尺寸 × 畫面量「棋盤外框位置大小、格距、是否捲動、超出像素」，存成 `check/baseline.json`。
3. `check/check_coords.mjs`（Playwright；兩儀殿部分照 `docs/design/duel-watch-follow-2026-11-13/check/check_follow.mjs` 的寫法）：
   - 開著：每種棋盤都有 15 個字母、15 個數字；A 在最左、P 在最右、1 在最下、15 在最上；字的位置對得上格線（讀繪製時記錄的座標，或 hook 繪製函式）；顏色＝目前樣式的 `label`；換一張棋盤樣式後顏色跟著變。
   - 點擊對位：開著時點「H8」位置 → 落在正中心那一點（天元）；點四個角 → 落在 A1、A15、P1、P15。
   - 關著：與 `baseline.json` 逐項相同（位置、大小、格距）。
   - 開著：格距 ≥ 基準的 95%；上面「不可以擠壞」的每一條。
   - 設定頁：有「棋盤座標」開關、預設開；切換立刻重畫；重新整理後記得；`game.html` 切了 `duel.html` 也跟著。兩儀殿對局中切換：仍在房間、WebSocket 沒重連。
   - 四語 × 兩種常用尺寸：設定頁加了一列後仍不捲動。
   - 教學盤、`score.html`、商店預覽盤、棋具頁預覽盤：開關開或關，畫出來都跟改動前一樣。
   - 既有標記對位：最後一手點、手順數字、連五框在開著時畫在正確的交叉點上。
   - 全程沒有 pageerror。
   - 負向測試一項。
   - 截圖（開著）：zh 的 320×568、360×640、375×667、412×915、768×1024 解題畫面各一；360×640 兩儀殿五子棋對局、VCF 觀戰、賽後回看；320×568 象牙塔研究盤；一張深色棋盤（夜墨）與一張圖片棋盤（星空或泳池）看字的對比。**自己看每一張**，把問題寫進 REPORT：字有沒有被棋子蓋住、太小看不清、貼到邊、跟星位或格線打架。

## REPORT.md 格式

用了多少留白、格距縮了多少（每個尺寸一列的表）／共用程式怎麼切的／每項檢查的完整輸出／截圖裡看到的問題／改動前就會捲動的組合清單／沒做到或不確定的事（老實寫）。
