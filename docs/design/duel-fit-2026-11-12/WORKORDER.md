## 使用者回報（2026-11-12）
「Pixel 10 在兩儀殿五子棋對戰中，認輸按鈕似乎要往下捲才看得到。」
這個遊戲的規則是**所有畫面都不可捲動**。Pixel 10 的 CSS 視窗大約 412 寬；Chrome 有網址列時高約 780～800、網址列收起約 840～860、裝成 App（PWA）全螢幕約 915。使用者可能調過「顯示大小／字型大小」，那樣 CSS 視窗會更小（例如 360×690、384×740）或字更大。不知道他是哪一種，也不知道是哪種規則的房間，所以都要查。

## 派工者已經看到的線索（是假設，要你驗證，不要直接當結論）
`duel.html`：
- 棋盤大小由 `layout()`（約 888 行）用 JS 算：`window.innerHeight − 房間畫面其他元素的高度`。
- `layout()` 只在這些時候跑：`show()`、視窗 `resize`、以及收到房間更新時 `sig` 有變（約 598–600 行，`sig = r.state + (me >= 0) + !!r.watchers + phaseKind()`）。
- 所以**任何不在 `sig` 裡、卻會改變其他元素高度的變化**都不會重算棋盤，底部按鈕列（`#rActs`，認輸在裡面）就被擠出畫面。可疑的有：
  1. `#status` 狀態列的字變長、換成兩行（塔拉開局提示、兩下才落子的提示、對方申請研棋那句等）。
  2. `#facts` 換行、`#rSub` 副標變化。
  3. 網頁字型（Chakra Petch 等）晚載入，載完後各列高度變了但沒重算。
  4. 底部按鈕列從 2 顆變 3 顆（出現「申請研棋」）時按鈕字換行變高。
  5. `layout()` 加總高度時沒算到 margin／gap，或 `.app` 用 `100dvh`、`layout()` 用 `window.innerHeight`，兩者在手機 Chrome 網址列伸縮時不一致。
  6. 系統字型放大（使用者把字調大）時各列比預期高。
