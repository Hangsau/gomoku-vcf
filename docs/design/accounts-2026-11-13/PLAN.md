# Gomoku Rush 登入帳號：計畫（2026-11-13）

狀態：**等使用者確認方向**。確認後照階段順序做，每階段驗收＋commit＋部署後才進下一階段。施工派 cc2，計畫與驗收由主 session。

## 使用者要的（2026-11-13 原話整理）

- 「做登入帳號吧」——起因：朋友的邀請連結開在別的瀏覽器時，暱稱、戰績、棋具沒跟過來。
- 「後臺需要做帳號管理」
- 「戰績、過去紀錄都跟著走」「所有覆盤都可以記錄」

## 現況（調查結果，2026-11-13；行號以當時為準，動手前 grep 確認）

- **沒有帳號**。瀏覽器裡有兩套互不相通的匿名編號：`vcfgame.vid`（象牙塔、教學、商店）與 `vcfgame.duel.id`（兩儀殿）。暱稱 `vcfgame.nick` 只是顯示名。
- **排行榜各表（`runs`、`practice`、`blitz`、`mirror`、`eye`）只存暱稱**，沒有任何編號；暱稱不唯一、沒有防冒名。有編號的只有 `tower`、`learn`、`owned`（vid）。
- **沒有任何地方存「這個人現在幾段」**：本機只存起始段位，伺服器只有每局的 `final_rank`。
- **今日棋局 `vcfgame.today`**：單人＋兩儀殿每局都寫，只在這台裝置，上限 300 筆，畫面只顯示今天。單人局的完整內容沒有上傳成「可回看的局」。
- **兩儀殿每局**在對戰伺服器（Durable Object 儲存 `rec:<id>`／`full:<id>`）有完整副本，帶兩位玩家的 `duel.id`，沒有清除程式。
- 後台 `rush.hangsau.app/admin` 靠 Cloudflare Access 驗證，分頁：留言、回報、數據、計分、題庫、棋具。

## 做完後的樣子

- 設定頁有「帳號」：用 Google 或信箱驗證碼登入；每個瀏覽器登入一次。沒登入照樣能玩（跟現在一樣）。
- 登入後，在任何瀏覽器／裝置：同一個暱稱、同一份戰績、同一份領過的棋具、同一份教學進度、同一份對局紀錄。
- 「我的紀錄」頁：自己所有對局（單人各模式＋兩儀殿），不限今天，點進去可覆盤。
- 排行榜上，登入玩家的名字有標記（代表這個暱稱是本人）；帳號之間暱稱不可重複。
- 後台「帳號」分頁：搜尋／列出帳號、看某人的戰績與對局、改暱稱、停用／恢復、把舊的暱稱紀錄指給某個帳號、刪除帳號（二次確認）。

## 關鍵設計決定（已定，不再問）

| 項目 | 決定 | 理由 |
|---|---|---|
| 登入方式 | 信箱驗證碼＋Google，兩種都做；**信箱驗證碼先做** | Google 登入在 LINE／FB 等內建瀏覽器常被 Google 擋；信箱驗證碼哪裡都能用，也不需要先去 Google 後台建設定 |
| 寄信 | Cloudflare Email Sending，寄件網域 `hangsau.app` | 已在同一個 Cloudflare 帳號；DNS 我設 |
| 登入狀態 | 伺服器發一把長效 token（存 localStorage，請求帶 `Authorization: Bearer`）；D1 `sessions` 表存雜湊，可逐一撤銷 | 排行榜 API 在 `workers.dev` 網域，跟頁面不同網域，cookie 不好用 |
| 身份主鍵 | 新的 `uid`；`links` 表把 `vid`、`duel.id` 對到 `uid` | 兩套匿名編號都保留，舊資料靠它們串 |
| 匿名紀錄合併 | 登入時把這個瀏覽器的 `vid`、`duel.id` 綁到帳號；綁過別的帳號的編號不搶（先綁先贏，後台可改） | 避免共用裝置時互搶 |
| 對戰伺服器認人 | 連線時帶 token，對戰伺服器向排行榜 API 驗一次換 `uid`；同一 `uid` 多處連線沿用現有「只留最新、舊的顯示已在別處開啟」 | 現有機制已處理重複連線 |
| 段位 | 新增「帳號目前段位」＝每個模式最近一局的 `final_rank`，另存最高段位 | 現在沒有地方存 |
| 對局紀錄 | 新表 `games`（uid、時間、來源、模式、摘要、完整內容），單人與兩儀殿結束時各寫一筆；登入時把本機 `vcfgame.today` 的存貨補傳 | 「所有覆盤都可以記錄」 |
| 不做 | 密碼登入、頭像、好友、跨帳號合併畫面（後台手動處理） | 範圍控制 |

## 一件需要使用者決定的事

**登入前、別的瀏覽器留下的舊排行榜紀錄**（只有暱稱、沒有編號）沒辦法證明是誰的。建議：不自動認領；由你在後台「帳號」分頁把「暱稱 X 的舊紀錄」指給某個帳號。替代做法是「登入時自動認領同暱稱的舊紀錄」，但任何人取同一個暱稱就能拿走別人的戰績。

這個瀏覽器自己留下的紀錄（今日棋局、教學進度、棋具、象牙塔、兩儀殿對局）不受影響，登入時一定會併進帳號。

## 個資

- 會開始蒐集信箱（與 Google 帳號識別碼）。需要：登入畫面一行告知用途（只用來登入與找回帳號）、一頁簡短的隱私說明、玩家可在設定頁刪除自己的帳號（連同信箱）。信箱只有後台看得到，排行榜與對戰只顯示暱稱。
- 驗證碼：6 位數、10 分鐘有效、同信箱與同 IP 限次數；資料庫只存雜湊。

## 階段

| 階段 | 內容 | 驗收 |
|---|---|---|
| 1 帳號核心 | D1：`users`、`sessions`、`links`、`login_codes`；API：寄驗證碼、驗證、登出、`/me`、改暱稱（帳號間唯一）、刪除自己；寄信網域設定；設定頁「帳號」區（設計稿 A 當時已留位置）；登入時綁 `vid`＋`duel.id`；四語、不捲動 | 本機 wrangler＋Playwright：登入、登出、第二個瀏覽器登入同帳號看到同暱稱；真的收得到信（我自己的測試信箱不適用時請使用者收一次） |
| 2 資料跟著走 | 各寫入路由在有 token 時寫 `uid`（各表加 `uid` 欄，只新增）；`owned`、`learn`、`tower` 依 `links` 歸戶；教學進度、棋具選擇、起始段位等偏好上傳／下載；帳號目前段位與最高段位；排行榜登入標記 | 瀏覽器 A 玩、瀏覽器 B 登入後看到同一份；沒登入的行為與現在逐項相同 |
| 3 對局紀錄 | `games` 表；單人各模式結束寫入；兩儀殿結束由對戰伺服器寫入（對戰伺服器驗 token）；登入時補傳本機存貨；「我的紀錄」頁＋覆盤（沿用現有研究盤與兩儀殿回看） | 兩個帳號對戰一局，雙方各自的紀錄頁都有、可覆盤；單人各模式各一局 |
| 4 後台帳號管理 | 「帳號」分頁：搜尋、列表、個人頁（戰績、對局、綁了哪些編號、登入裝置）、改暱稱、停用／恢復、指派舊暱稱紀錄、刪除（二次確認）、撤銷登入 | 每個動作在本機資料庫驗證前後狀態；停用的帳號 token 立刻失效 |
| 5 Google 登入 | Google 登入按鈕（在允許的瀏覽器顯示）；Worker 驗 ID token；同信箱自動對到同一個帳號 | 一般瀏覽器可登入；內建瀏覽器只顯示信箱驗證碼 |

每階段：施工單 → cc2 → 主 session 看 diff＋重跑檢查＋截圖 → commit → `schema.sql`（只新增）→ `deploy_worker.sh` →（階段 3 起）對戰伺服器 → `deploy_rush.sh` → 線上驗證 → 更新本檔狀態。

## 風險與對策

- **動到正式資料庫**：只新增表與欄位，不改不刪既有資料；歸戶寫的是新欄位，可以整欄清掉重來。刪除帳號是唯一的破壞性動作，只刪該帳號的列。
- **對戰伺服器部署會中斷進行中的對局**：部署前看大廳沒人；只在階段 3 部署一次。
- **寄信進垃圾信／寄不出去**：階段 1 先實測；不通就改用其他寄信服務，登入流程不變。
- **冒名**：帳號暱稱唯一＋排行榜標記；沒登入的人仍可取同名，但沒有標記。
- **`game.html` 已經很大**：帳號邏輯放新檔 `game/account.js`（同 `shop.js` 的做法）。
- **多 session 同時改 VCF**：開工先在 session-coord 登記；commit 一律列檔名。
