## 伺服器（worker.js）
1. 每間房多兩個欄位：
   - `priv`：布林，來自 `create` 訊息的 `priv`（沒帶當 false）。
   - `code`：6 個字的邀請碼，字元表 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去掉容易看錯的 I、O、0、1），開房時亂數產生，跟現存房間不重複。
2. 大廳清單 `t: 'lobby'`：私人房**也列出來**（使用者 2026-11-12 追加：「私人房也可以列大廳，知道有私人房，進不去」），每間房多帶 `priv`；清單裡任何房間都**不帶** `code`。私人房在清單裡照樣顯示狀態（等待中／對局中）與座位上的暱稱。
3. 送給房內／看房的人的 `t: 'room'`：帶 `code` 與 `priv`。
4. 新訊息 `{ t: 'join', code }`：把 code 去空白、轉大寫後找房間。找到就跟 `view` 那間房一樣處理（進去看，還沒入座）；找不到回 `err` 代碼 `nocode`。
5. 私人房不能用房號硬進：對私人房的 `view`／`sit`，只有「已經用正確邀請碼 join 過這間、或本來就在這間房裡」的連線才放行，其他回 `err` 代碼 `nocode`。（在連線物件上記一個已通過的房號集合即可。）公開房的 `view`／`sit` 照舊。
6. 防亂猜：同一條連線 60 秒內 `join` 失敗滿 10 次，之後 60 秒內的 `join` 一律回 `err` 代碼 `slow`。
7. 「再來一局」沿用同一間房，`code` 不變。房間關閉後 code 自然失效。
8. 在 `code` 產生處留一行註解：之後有帳號時，邀請網址會多帶 `from=<邀請人>`，伺服器這邊不用改格式。

## 頁面（duel.html）
1. **開房表單**：加一組「誰能進」兩顆 chips——「公開」（列在大廳，誰都能入座）／「私人」（大廳看得到這間房但上鎖，要邀請碼才進得來），下面一行小字說明目前選的那種。預設公開；上次選的記在 `store` 鍵 `vcfgame.duel.priv`。送 `create` 時帶 `priv`。
2. **房間畫面**：上方列加一顆「邀請」圖示按鈕（44px 以上，沿用 `.icob`；位置放在既有按鈕旁，不新增列）。私人房在房名旁顯示一個小鎖圖示。
3. **邀請面板**（底部 `.modal`，id `mInvite`）：
   - 大字顯示 6 碼邀請碼（等寬、字距拉開，`--num` 字型）。
   - 「分享連結」按鈕：`navigator.share({ title, text, url })`；不支援就退回複製並顯示「已複製」。
   - 「複製連結」按鈕：複製網址，顯示「已複製」。
   - 一行說明：「朋友點連結，或在大廳按『輸入邀請碼』，就會進到這間房。不用安裝、不用註冊。」
   - 邀請網址：`location.origin + location.pathname + '?r=' + code + '&lang=' + 目前語言`。
   - 開了私人房、且對手座位還空著時，進房後自動打開這個面板一次（公開房不自動開）。
4. **大廳的私人房**：清單裡私人房那一格加鎖圖示與「私人」字樣，樣式比公開房暗一階；點它不送 `view`，直接打開下面的「輸入邀請碼」面板（面板上方多一行「這是私人房，要邀請碼才能進」）。輸入的碼對到的是哪間房就進哪間（不必是剛點的那間）。已經用邀請碼進過的私人房（本次連線）再點可以直接進。
4b. **大廳**：在「開房」附近加一顆「輸入邀請碼」按鈕 → 底部面板（id `mJoin`）：一個輸入框（最多 6 字、自動轉大寫、`autocapitalize="characters"`、`inputmode="text"`、`autocomplete="off"`）＋「進房」按鈕。送 `join`。`nocode` 顯示「找不到這間房，可能已經關了」；`slow` 顯示「試太多次了，等一下再試」。
5. **網址帶 `?r=CODE`**：連上伺服器（收到 `hello`）後自動送 `join`，然後用 `history.replaceState` 把 `r` 從網址拿掉（重新整理不會重複進）。找不到房間時跳一個面板：「這間房已經關了」＋「開一間新的」按鈕（打開開房表單）＋「回大廳」。`?lang=` 的既有行為不變。
6. 還沒填暱稱的人照既有流程（入座時才要求），看房不擋。
7. 所有新文字加進 `I18N` 四種語言（zh／en／ja／ko），簡短。

## 驗證（結果寫進回報）
本機起對戰伺服器：`npx wrangler@4.158.0 dev -c game/duel-server/wrangler.toml`（預設 127.0.0.1:8787；記 PID，結束只關這個 PID 樹）。另起靜態伺服器（記 PID）。`duel.html` 在本機怎麼連本機伺服器，看檔內 `WS_` 開頭的常數與判斷。用 Python Playwright 開多個獨立的瀏覽器 context 當不同玩家（寫法可參考 `tools/promo/rush_promo.py`）。
1. A 開**私人**房：B 的大廳清單看得到這間、有鎖圖示與「私人」字樣；B 點它會跳出輸入邀請碼面板而不是進房；B 直接送 `view`／`sit` 那個房號 → 收到 `nocode`、進不去。
2. B 在大廳用「輸入邀請碼」輸入 A 的碼（故意打小寫、中間夾空白）→ 進到 A 的房、能入座、對局開始（雙方各下一手成功）。
3. A 開**公開**房：B 的大廳看得到；C 不看大廳、直接用邀請碼也進得去。
4. 用網址 `duel.html?r=<碼>` 開新 context：自動進到那間房；網址裡的 `r` 被拿掉；重新整理後不會報錯。
5. 用不存在的碼：面板顯示找不到；`?r=不存在的碼` 顯示「這間房已經關了」面板，按「開一間新的」會打開開房表單。
6. 同一連線連續送 11 次錯的 `join`：第 11 次收到 `slow`。
7. 大廳清單的原始訊息裡沒有任何 `code` 欄位（把收到的 `lobby` 訊息印出來檢查）。
8. 「再來一局」後邀請碼不變。
9. 不捲動：大廳、開房表單、房間（等人中）、邀請面板、輸入邀請碼面板、房間已關面板，在 375×667 與 360×640 × zh／en／ja／ko：`scrollHeight <= innerHeight`、`scrollWidth <= innerWidth`，面板完整在畫面內。房間畫面另外確認認輸鈕、離開鈕仍完整在畫面內（今天剛修過這個問題）。列成表，任何一格超出要修到 0。
